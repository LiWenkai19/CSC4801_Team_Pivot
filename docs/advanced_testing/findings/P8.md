## 面试时段创建的 422 业务响应体不符合 OpenAPI 声明的 `HTTPValidationError` 结构

- 需求条款：FP-SCHED-1（拒绝非法时段）；`SPEC.md` §Employer interview slots（开始时间不合法时返回 `422`），响应结构由 FastAPI 自动生成的 OpenAPI `HTTPValidationError` 声明
- 复现命令：`python tests/advanced/run.py apifuzz --out <仓库外空目录>`；本次运行中雇主轮 `POST /employer/interview-slots` 的 10 个写样例有 9 个命中该缺陷
- 最小输入：已登录且带 CSRF 的雇主执行
  `POST /employer/interview-slots`，JSON body：
  `{"starts_at": "2000-01-01T00:00:00Z"}`
- 期望：`422`，响应体符合 OpenAPI 的 `HTTPValidationError`，即
  `{"detail": [{"loc": ..., "msg": ..., "type": ...}]}`（`detail` 是数组）。
  实际：`422`，响应体为 `{"detail": "Slot must start in the future"}`（`detail` 是字符串），
  Schemathesis `response_schema_conformance` 报 `ST108 Response violates schema`
  （"Slot must start in the future" is not of type "array"）。
- 定位线索：`backend/app/interview/router.py:17` 把 `InvalidSlotError` 映射为 422，
  `backend/app/interview/router.py:37` 用 `HTTPException(422, str(error))` 返回字符串 detail；
  业务校验在 `backend/app/interview/service.py:44` 与 `:47`。`backend/app/main.py:32-41`
  的自定义 422 处理器只覆盖 `RequestValidationError`（Pydantic 请求校验），
  不覆盖路由自己抛出的 `HTTPException`，因此出现了同一状态码两种响应体。

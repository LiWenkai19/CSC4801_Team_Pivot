## 1. 蜕变（`test_metamorphic_workflows.py`）

| ID | 原输入 → 变换 | 关系 |
|---|---|---|
| M1 | 先建时段再投递+改状态 ↔ 先投递+改状态再建时段 | 候选人可用时段集合相同 |
| M2 | 给系统添加无关雇主的职位、时段、申请 | 原候选人的推荐顺序（相对次序）与可用时段不变 |
| M3 | 给职位要求技能加大小写/空白/重复变体 | 推荐分数与顺序不变 |
| M4 | 候选人资料只改 resume_text | 推荐分数与顺序不变（简历不是匹配输入） |
| M5 | 申请状态 Interviewing → Rejected → Interviewing | 若期间无预约，可用时段集合与原来相同 |

每个 ID 一个测试，用真实接口；规模小（≤ 10 个对象）。

## 2. 内蜕变（`test_defense_layers.py` + `variants.py`）

对以下每条规则，构造"关掉一层"的变体，用相同输入运行原版与变体，比较结果：

| ID | 规则 | 变体（monkeypatch） | 期望 |
|---|---|---|---|
| I1 | 一个时段只能被预约一次 | 让 `book` 里的"Slot already booked"预检查询恒返回 None | 数据库唯一约束兜底：第二次预约仍失败 409 `Slot already booked`，预约表 1 行 |
| I2 | 并发预约单赢家 | 去掉行锁：把 `select(...).with_for_update` 替换为不加锁的版本（monkeypatch `Select.with_for_update` 为返回 self 的函数），用 `threading.Barrier(2)` 两个候选人同时预约 | 仍恰好 1 个 201、1 个 409，表里 1 行（唯一约束兜底） |
| I3 | 重复投递被拒 | 让 `apply` 的已投递预检恒返回 None | 唯一约束兜底：409，申请表不增加 |
| I4 | 匹配实现对集合实现方式不敏感 | 把 `normalize_skills` 包一层改为返回顺序反转的列表 | 所有分数与排序不变 |
| I5 | 删除有依赖的职位被拒 | 让 `delete_job` 的依赖检查恒为"无依赖" | 记录实际结果：若数据库外键/约束拦截 → "有兜底"；若删除成功 → "单层防护"（这不是 bug，是事实记录，写进表格） |

每个变体测试都同时跑一次原版作为对照，结论用 `evidence("defense_layers", ...)` 输出。

**注意**：I2 是真实并发测试，按 PEER_REVIEW 对并发证据的要求使用 Barrier；最多重复 5 次，结果必须每次一致。
两个线程必须用**各自独立的 `Session` / TestClient 请求**，否则共享连接会把并发变成串行，测试会"假通过"。
I2 必须额外证明"并发真的发生了"：记录两个请求进入 `book` 的时间戳或用第二个 Barrier 卡在加锁之后，
在 evidence 里写出两者重叠的证据。

已有可参考的写法：`backend/tests/candidate/test_booking.py::test_real_postgres_two_candidates_compete_for_one_slot`。
I3/I1 相关的投递路由是 `POST /candidate/jobs/{job_id}/applications`，申请人列表是 `GET /employer/jobs/{id}/applications`。

# 任务 P11：覆盖率、汇总报告、文档与 CI 收口

**分支**：`test/P11`　**依赖**：P0–P10、P12 中**已完成的任务全部合并**　**预计**：4–5 小时
**这是唯一可以修改 README / INSTALL / DOCKER 的任务。**

## 目标

1. 测量覆盖率；2. 用脚本从各模式产物生成统一报告；3. 更新面向评分者的文档；4. 把 advanced CI job 转为必过。

## 允许修改

- 新增：`tests/advanced/coverage/`（`NEEDS_DB`、`SLOW`、`entry.py`）、`tests/advanced/report.py`
- 新增：`docs/advanced_testing/ADVANCED_REPORT.md`、`docs/advanced_testing/findings/SUMMARY.md`
- 修改：`README.md`、`INSTALL.md`、`docs/DOCKER.md`（或根目录 `DOCKER.md`，以仓库内实际存在的为准）、
  `tests/advanced/README.md`、`.github/workflows/ci.yml`

## 具体要求

### 1. 覆盖率（`coverage/entry.py`）

- 单元套件：`pytest --cov=backend/app --cov-branch` 跑 `tests/unit`（环境变量照 `tests/run_tests.py`）。
- 集成套件：同样方式跑 `backend/tests`（需要 PG；用 `ADVANCED_PG_URL` 设置两个 `*_TEST_DATABASE_URL`）。
- 高级套件：对 `stateful`、`differential`、`intramorphic` 收集覆盖率。
- 合并后输出各模块的语句/分支覆盖率，写 `$ADVANCED_OUT/coverage/coverage.json` 与 `coverage.xml`。
- **先测量，再决定门槛**：门槛设为"单元套件实测值向下取整到 5 的倍数"，写进 CI；不要拍脑袋设 90%。

### 2. 汇总（`report.py`）

- 输入：一个 `--out` 目录（`run.py all` 的产物）。
- 输出：`docs/advanced_testing/ADVANCED_REPORT.md`，每个技术一节：讲义出处、命令、关键数字（从 JSON 读，不手填）、
  耗时、种子、commit SHA、局限、详细文档链接（`LTL.md`、`FORMAL_MATCHING.md`、`MUTATION.md`……）。
- 顶部一张总表：技术 | 讲义 | 规模 | 结果 | 证据文件。
- 本地执行 `python tests/advanced/run.py all --out <dir>` 后 `python tests/advanced/report.py <dir>` 生成报告并提交。

### 3. 缺陷汇总

合并所有 `docs/advanced_testing/findings/P*.md` 到 `SUMMARY.md`：去重（按根因）、状态（未修/已修/不是缺陷）。

### 4. 文档

- `README.md`：
  - 新增"高级测试与验证"小节：一段概述 + 指向 `ADVANCED_REPORT.md` 的链接 + 命令。
  - 需求–测试映射表：在 FP-MATCH-1、FP-SCHED-1/2/3、FP-SEC-1、FP-TEST-1 行追加新的具名测试
    （P1 的 9 个属性测试名必须出现在 FP-MATCH-1 行，因为它们在必测套件里）。
  - 把过时的测试数字更新为实测值（从 `ADVANCED_BASELINE.md` 与本次运行读取）。
  - **注意**：README 还有别的组员在重写。开工前 `git pull` 最新 main；只改与测试相关的段落；
    冲突时保留对方的新结构，把测试内容移到新结构对应位置。
- `INSTALL.md`：新增"Advanced test suite (optional)"小节：依赖安装、`PG_BIN`、命令。
- `DOCKER.md`：一句话说明"Hypothesis 已在 requirements.lock 中、随镜像安装，必测命令在镜像内可运行；
  高级套件（mutmut、z3、schemathesis、coverage）不进入镜像，在开发环境或 CI 中运行"。

### 5. CI

- `advanced` job 去掉 `continue-on-error`；仍只跑 `fast`。
- 新增 `advanced-slow` job：`on.schedule`（每周一次）与 `workflow_dispatch` 触发，跑 `all`，
  上传产物；不阻塞 push。需要在 `on:` 下加 `schedule`，并用 `if: github.event_name != 'push' && github.event_name != 'pull_request'`
  控制只在定时/手动时运行。
- `unit` job 增加覆盖率门槛（`--cov-fail-under=<门槛>`）——只有当 P1 合并后的单元套件实测稳定时才加。

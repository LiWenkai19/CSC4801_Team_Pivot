# 任务 P7：变异测试（mutmut）与测试补强

**分支**：`test/P7`　**依赖**：P0 已合并；最好 P1 也已合并（属性测试能杀更多变异体）　**预计**：6 小时

## 目标

用工具化变异测试量化必测单元套件的缺陷检出能力（mutation score），逐个归因幸存变异体，
对"缺测试"类幸存者在 `tests/unit/` 补测试，最终给出补强前后的分数对比。对应讲义 L14 slide 28。

## 允许修改

- 新增：`tests/advanced/mutation/`（`SLOW` 空文件、`entry.py`、`setup.cfg` 或 mutmut 配置、`survivors.md` 草稿可选）
- 新增：`tests/unit/test_mutation_hardening.py`（补强测试**只能放这个新文件**，不改其他单元测试文件）
- 新增：`docs/advanced_testing/MUTATION.md`
- 新增：`docs/advanced_testing/findings/P7.md`（仅当发现业务缺陷）

## 先读

- `tests/specialized/mutation_checks.py`（已有 8 个手写变异体；了解思路，**不要修改**）
- `tests/run_tests.py`、`tests/unit/conftest.py`
- mutmut 文档（版本以 `tests/advanced/requirements.txt` 为准）

## 范围

只变异这些文件：

- `backend/app/employer/matching.py`
- `backend/app/users/service.py`
- `backend/app/candidate/service.py`
- `backend/app/employer/service.py`
- `backend/app/interview/service.py`

测试集：`tests/unit/`（纯替身，快；不要用集成测试，太慢）。

## 具体要求

1. `entry.py`：
   - 把 `backend/` 复制到 `$ADVANCED_OUT/mutation/work/`（**绝不在仓库原地变异**），在副本里运行 mutmut；
   - 设置与 `tests/run_tests.py` 相同的单元测试环境变量；
   - 每个变异体超时 30 秒；并行数 = CPU 核数 − 1；
   - 结束后导出：总数、killed、survived、timeout、suspicious、按文件分组的统计，写
     `$ADVANCED_OUT/mutation/result.json`；把幸存变异体的 diff 写 `survivors/*.diff`。
   - 运行前后对仓库内 `backend/app` 做 SHA256 校验，任何变化 → 失败退出。
2. 首次全量运行，记录**基线分数**。
3. 逐个归因幸存者（写进 `docs/advanced_testing/MUTATION.md` 表格）：
   - **等价变异**（行为不变，例如 `int(x//y)`）→ 说明原因；
   - **缺测试** → 在 `tests/unit/test_mutation_hardening.py` 补测试，测试名写明它杀掉的变异体 ID，
     期望值来自需求而不是实现；
   - **不可达/防御性代码** → 说明理由。
4. 补强后重跑，记录**最终分数**。目标：`matching.py` 100%；其余文件比基线显著提高。
   不要为追分数写"复述实现"的测试。
5. 若 mutmut 与本项目（SQLModel、pytest 8、Windows 路径）不兼容且 1 小时内无法解决：
   改为在 `entry.py` 里实现**基于 AST 的变异器**（`ast.NodeTransformer`：比较运算符翻转、
   `//`→`/`、常量 ±1、`and`↔`or`、删除 `raise`、`return X`→`return None`），
   逐个变异体在副本里运行单元测试；汇报里说明降级原因。

## 验收

```sh
python tests/advanced/run.py mutation
python tests/run_tests.py
```

- 产出基线/最终 mutation score、幸存者归因表、补强测试；必测套件全绿；仓库内源码 SHA 未变。
- 运行时间写进汇报（预计 10–40 分钟）。

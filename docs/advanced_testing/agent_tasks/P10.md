**分支**：`test/P10`　**依赖**：P0 已合并；P7 合并后可补"变异杀伤力"一节　**预计**：4 小时

## 目标

把讲义 L14 Exercise 1（AI 辅助测试生成）和 Exercise 3（断言编写与质量评估）在本项目上
**原样复刻成可复现实验**：只看契约、不看实现生成测试，运行，归因，再与手写测试比较。

## 关键约束：盲测

为了让结论可信，生成阶段**不能看实现**：

1. 由你（主会话）写契约，只读 `docs/REQUIREMENTS.md`、`SPEC.md`，以及函数签名（`def` 那一行与 docstring）。
2. 调用**一个新的子代理**负责生成测试，只给它：契约文件 + prompt + 函数签名 + import 路径。
   明确告诉它"不要打开 `backend/app/` 下的任何文件"。
3. 子代理交回后，**先 commit 生成文件**（commit 信息含"generated before reading implementation"），再运行。

## 流程（每个函数）

1. **契约**（`contracts/F<n>.md`）：输入、输出、异常、副作用、边界；你自己手算 3 个期望值写进去。
2. **Prompt**（`prompts/F<n>.txt`）：照 L14 slide 12 的写法——
   "先按需求映射有效/边界/无效分区；从契约计算期望值并写出算术；检查精确异常类型；
   不要从实现推断期望；列出歧义；不要修改生产代码。"F2 额外要求"每个被拒绝的调用，
   断言异常类型**并且**会话状态未改变（未 commit、已 rollback）"（L14 slide 26）。
3. **生成**：子代理产出 `generated/test_F<n>.py`（或 `.mjs`），commit。
4. **运行**：`pytest generated/ -v` 记录每个用例结果。
5. **归因**每个失败：实现 bug（写 findings）/ 契约歧义 / 生成错误（期望值算错、API 用错）。
6. **对比手写测试**：同一函数的现有手写测试（`tests/unit/test_matching.py`、`test_scheduling.py`、`test_rendering.py`）——
   分区覆盖对照表、用例数、独有发现。
7. **断言杀伤力**（若 P7 已合并）：用 P7 的变异器在 F1/F2 上跑生成测试与手写测试，比较各自杀掉的变异体数量。
   P7 未合并时，手写 5 个变异体（照 L14 slide 28：边界 `>=`→`>`、常量改变、去掉一项检查）用 monkeypatch 注入。

## `docs/advanced_testing/LLM_TEST_EXPERIMENT.md`

## 验收

- 三个函数都有契约、prompt、生成测试、运行结果、归因、对比。
- 生成文件的 commit 早于任何读取实现的动作（汇报里给出 commit SHA 顺序）。
- `python tests/run_tests.py` 仍全绿（实验测试不进必测套件）。

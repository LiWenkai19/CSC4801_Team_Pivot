## 目标

实现一个有限轨迹 LTL 求值器，用它对 P2 产生的业务轨迹检查时序性质；
附带检查器自检，以及（加分项）讲义 L13 的 relax/restrict 性质精化演示。

## 具体要求

### 1. `support/ltl.py`

- AST：`Atom(pattern)`、`Not`、`And`、`Or`、`Implies`、`X`（强下一步：最后一步时为假）、
  `WX`（弱下一步：最后一步时为真）、`G`、`F`、`U`。
- 参数化原子：命题模式允许变量，如 `booked:?a:?s`。提供 `forall(vars, formula)`：
  从轨迹中出现过的命题里收集变量取值，对每组取值实例化后求值（有限域全称量化）。
- `evaluate(formula, trace, i=0) -> bool`，有限轨迹语义，写清楚 docstring。
- `explain(formula, trace) -> str`：失败时给出第一个违反位置和该步的事件。
- 用简单解析器或 Python 构造器都可以；**不要**引入第三方 LTL 库。

### 2. `ltl/test_checker_selftest.py`（不需要数据库，但目录有 NEEDS_DB 也没关系）

对每个运算符各写手工小轨迹：至少 3 条满足、3 条违反，期望值手算写死。
另外对 `G(p -> X q)`、`p U q`、`F G p` 各做真值表式参数化测试。

### 3. `ltl/properties.py` + `ltl/test_booking_traces.py`

性质（每条对应需求条款，写在注释里）：

| ID | 性质 | 条款 |
|---|---|---|
| L1 | `forall a,s: G(booked:a:s -> WX G(!available:s))` 预约后时段永不再可用 | FP-SCHED-1/2 |
| L2 | `forall a: G(new_booking:a -> status:a:Interviewing)` 只有面试中才能新建预约 | FP-SCHED-2 |
| L3 | `forall a,s: G(booked:a:s -> G(booked:a:s))` 预约一旦建立永不消失（状态变化不解绑） | FP-SCHED-2 |
| L4 | `forall a,s: G(booked:a:s -> G(slot:s))` 已预约时段永不被删除 | FP-SCHED-1 |
| L5 | `forall a: G(applied:a -> G(applied:a))` 申请不会消失 | FP-CAN-3 |

测试流程：如果 `$ADVANCED_OUT/stateful/traces/` 不存在，先在测试内以子进程运行
`python tests/advanced/run.py stateful --out <tmp>` 生成轨迹（或直接调用 P2 的状态机，
`max_examples=10`）。对全部轨迹求值，任何违反都 `pytest.fail(explain(...))`。
把 每条性质 × 轨迹数 × 满足数 写到 `evidence("ltl_results", ...)`。

**空真（vacuity）检查（必须做）**：形如 `G(p -> q)` 的性质，如果某条轨迹里 `p` 从未成立，它是"空真"满足的，
不能算作有效证据。对每条性质统计：前件至少触发一次的轨迹数（非空真满足数）与总触发次数，写进 evidence 和报告。
已知 P2 的轨迹里"删除已预约时段"只尝试了 2 次、成功预约 11 次，L1/L4 的非空真样本可能偏少；
若某条性质非空真满足的轨迹 < 5 条，在报告里如实写出，并说明它主要由 P2 的不变量和 P5 的模型检验补强，
**不要**为凑数修改 P2 的代码或权重（P2 已合并，归 P2 所有）。

P2 实际细节（已合并，读代码为准）：
- 申请人列表路由是 `GET /employer/jobs/{id}/applications`；
- 轨迹里每个 Hypothesis example 一个文件，25 个里约 2 个重复（Hypothesis 重放），统计时同时报告总数与去重数；
- 命题命名见 `tests/advanced/README.md` 第 8 节，含 `slot:` 与 `new_booking:`；状态值区分大小写。

### 4. 加分项：`ltl/refine.py`（relax/restrict 演示）

- 取一条**故意过强**的性质，例如 `G(status:a:Interviewing -> F booked:a:?s)`（"面试中的申请最终都会被预约"，
  业务上并不保证）。
- 实现讲义 slides 46–49 的思路：违反时随机（固定 seed）把一个运算符替换为更弱的（`X→F`、`G→F`、去掉合取项），
  直到所有轨迹都满足，输出精化链 `F → F' → F''` 与每步满足的轨迹比例；
  若某性质无反例，对其做一次 restrict（`F→G`、`F→X`）看是否出现反例。
- 写一个测试断言该演示可复现（同 seed 同结果）。

## 自检（必须做）

- 手写一条违反 L1 的合成轨迹（预约后同一时段再次 available），L1 必须判假，`explain` 指出正确步号。
- 在汇报里写出该输出。

# 任务 P8：基于 OpenAPI 的 API 属性模糊测试（Schemathesis）

**分支**：`test/P8`　**依赖**：P0 已合并　**预计**：5 小时

## 目标

从 FastAPI 自动生成的 OpenAPI schema 出发，用 Schemathesis 对**本地**后端做有界的属性模糊测试，
检查：无未分类 5xx、响应符合 schema、认证与授权状态码符合 FP-AUTH-3。

## 允许修改

- 新增：`tests/advanced/apifuzz/`（`NEEDS_DB`、`SLOW`、`entry.py` 或 pytest 文件、`hooks.py`）
- 新增：`docs/advanced_testing/APIFUZZ.md`
- 新增：`docs/advanced_testing/findings/P8.md`（仅当发现缺陷）

## 先读

- `backend/app/main.py`、四个 `router.py`
- `docs/REQUIREMENTS.md` FP-AUTH-3、FP-SEC-1
- Schemathesis 文档（版本以 `tests/advanced/requirements.txt` 为准；优先用其 Python API + ASGI 直连
  `app.main.app`，不起真实端口）

## 安全边界（必须遵守）

- 只对进程内 ASGI app 或 `127.0.0.1` 随机端口；数据库为一次性库。
- 每个操作 `max_examples ≤ 20`（可由 `ADVANCED_MAX_EXAMPLES` 下调），固定 seed，单 worker，无并发。
- 不做负载、不做长时间运行；总时长目标 < 5 分钟。

## 具体要求

### 三轮

1. **匿名轮**：不带认证，覆盖全部操作。断言：除 `/users/register`、`/users/login` 外，
   所有受保护操作返回 401（或 422 校验先于认证时须记录并归因）；没有 5xx。
2. **候选人轮**：用夹具注册一个有资料的候选人，带其 Cookie + CSRF 头；
   只对 `/candidate/*` 与 `/users/me` 的 GET 运行 schema 一致性 + 无 5xx；对 `/employer/*` 断言 403。
3. **雇主轮**：对称地对 `/employer/*` 的 GET 运行；对 `/candidate/*` 断言 403。

写操作（POST/PATCH/DELETE）只在候选人/雇主轮中对**自己拥有的资源**运行，且限于 `max_examples=10`；
路径参数里的 UUID 由 Schemathesis 随机生成，期望 404/403/422，不得 500。

### 检查项

`not_a_server_error`、`response_schema_conformance`、`status_code_conformance`，
外加自定义检查：401/403/404 与上面的期望矩阵一致。

### 输出

- 每轮的操作数、请求数、各状态码分布、失败用例（含 Schemathesis 给的 curl 复现命令，**删除 Cookie 值**）
  写 `$ADVANCED_OUT/apifuzz/report.json`。
- 每个失败必须归因为：**真实缺陷**（写 findings）、**schema 漂移**（代码返回了 schema 未声明的状态码）、
  **测试配置问题**。不得用过滤器静默忽略。

## 降级

改用 Hypothesis + `TestClient` 手写请求生成器（从 `app.openapi()` 读路径与参数类型，生成随机 UUID/字符串/JSON），
保留同样的三轮与断言。汇报说明原因。

## 各页交互逻辑

### 页面 1：公司资料

- 入口：employer 从 NavPage 进入。
- 加载：`GET /employer/company` 显示 company_name、company_description。
- 编辑：表单提交 `PATCH /employer/company`，只传显式修改的字段；成功后刷新显示「已保存」。
- 异常：GET/PATCH 返回 404（未填资料）→ 提示「请先填写公司资料」并链接到现有 `/employer/details` 创建页（不新增创建功能，创建仍走 users 的 `POST /users/employer/profile`）；空白公司名前端拦截，服务端 422 错误原样显示；失败保留输入可重试。

### 页面 2：职位列表

- 加载：`GET /employer/jobs` 列表显示 title、company_name、required_skills、created_at；空列表显示「暂无职位」。
- 行内操作：查看详情/申请人（→ 页面 4）、编辑（→ 页面 3）、删除（`DELETE /employer/jobs/{id}`）。
- 删除结果：成功从列表移除；409 显示「有申请或面试时段，不能删除」；403/404 原样提示。
- 「新建职位」按钮 → 页面 3。

### 页面 3：职位表单（新建/编辑同组件）

- 新建模式空表单；编辑模式先 `GET /employer/jobs/{id}` 回填。
- 字段：title、description、required_skills（逗号分隔输入，提交时拆成数组）。
- 校验：标题/描述非空（去空白后判断），空白前端拦截。
- 提交：新建 `POST /employer/jobs`（201）；编辑 `PATCH /employer/jobs/{id}`（传 required_skills 即整体替换，空串拆出空数组表示清空）。
- 结果：成功跳回列表；403/404/422 显示对应错误；提交中禁用按钮防重复；失败保留输入。

### 页面 4：职位详情 + 申请人

- 加载：`GET /employer/jobs/{id}` 显示职位信息（含编辑按钮 → 页面 3）+ `GET /employer/jobs/{id}/applications` 申请人表。
- 申请人行：display_name、skills、match_score、status、booking（有预约显示起止时间，无显示「无」）。
- 改状态：每行状态下拉（Pending/Interviewing/Rejected/Accepted 四值），提交 `PATCH /employer/applications/{id}/status`，成功更新该行状态。
- 空态：暂无申请人显示提示；403（他人职位）/404（职位不存在）显示提示并给返回列表链接。

## API 与类型（必要关联改动）

- [types.ts](../frontend/src/types.ts) 增补（沿用现有共享类型位置）：`CompanyPublic`、`CompanyUpdate`、`JobCreate`、`JobUpdate`、`JobPublic`、`ApplicantPublic`、`BookingPublic`、`ApplicationStatus`（四值联合）、`ApplicationStatusUpdate`、`ApplicationStatusPublic`。字段与后端 [schema.py](../backend/app/employer/schema.py) 完全一致。
- 新增 `api/employer_api.ts`：9 个函数（getMyCompany、updateMyCompany、createJob、listMyJobs、getMyJob、updateJob、deleteJob、listJobApplicants、changeApplicationStatus），复用 [common_api.ts](../frontend/src/api/common_api.ts) 的 `requestWithToken`。
- DELETE 204 无响应体的处理：现有 `request` 总是 `response.json()`，**优先不动 common_api**，在 employer_api 内用带 token 的 fetch 兼容空响应。
- [App.tsx](../frontend/src/App.tsx) 注册新路由（机械接线）。

## 验收（五场景，前端可见行为）

| 场景 | 验证点 |
| --- | --- |
| 正常 | 五个页面主流程全通：看/改公司资料、职位增删改查、申请人列表、改状态后列表即时更新 |
| 非法参数 | 空白标题/描述/公司名前端拦截并提示；非法状态值不可选（下拉固定四值） |
| 未登录 | 直接访问 employer 路由被 RequireAuth 拦到登录页（已有机制） |
| 越权 | candidate 访问 employer 路由显示角色提示；服务端 403 的 detail 原样显示（隐藏按钮不是授权） |
| 不存在 | 职位/申请 404 显示提示 + 返回链接；公司资料 404 引导创建 |

另验证：请求失败显示错误且保留输入、提交中防重复、空列表空态。技术检查：`npm run build`（tsc + vite）与 `npm run lint`（oxlint）。前后端联调需后端在 8000 端口运行，完成后实际跑页面验证。

# Candidate Flow 缺陷修复记录

日期：2026-10-28。针对审计中确认的四项问题，修改范围为候选人独立应用。

1. 多标签页：其他标签页改变共享令牌时，仅清理当前页的身份状态；主动注销仍删除共享令牌。旧页需要重新登录或刷新以同步身份。
2. SQL日志：独立应用使用新的数据库会话，禁用SQL echo并隐藏参数；SQLite连接启用外键。队友的数据库模块和主应用未修改，其他应用入口必须由对应所有者自行接入安全设置。
3. 注册竞态：数据库拒绝重复邮箱后回滚并再次确认邮箱，返回原有的400提示；其他完整性错误继续抛出。此处通过模拟查重窗口和真实SQLite唯一约束验证，尚未验证PostgreSQL实际并发。
4. 职位推荐：批量读取职位技能、雇主资料和本人的申请记录，超过500项时分批查询，保留占位评分及排序；列表仍无分页。

回归覆盖见后端 `candidate_tests/test_bugfix_regression.py` 和浏览器 `e2e/session_security.spec.ts`。诊断脚本保留对大输入和登出后令牌仍有效的观察，不能将这些风险视作已修复。其他待决问题包括输入长度与数量上限、限流、服务端令牌撤销；需结合产品和部署策略处理。

验证：候选人统一检查中的后端回归为231 passed、1 skipped，前端单元测试4 passed，构建、lint和依赖检查通过；浏览器端到端11 passed。随后新增超过500个职位的分批边界测试，并与功能验收测试共同运行，70 passed；Ruff和团队文件归属检查通过。所有测试使用隔离数据，未验证真实PostgreSQL并发。

# 简历读取与修改

2026-10-26 用户确认：候选人仅读本人；已登录雇主仅可读取申请过自己职位的候选人；只有候选人本人可以修改。本规则替代此前“简历仅本人可见”的实现约定。

| 访问者 | 读取 | 修改 |
| --- | --- | --- |
| 候选人本人 | 200 | 200 |
| 其他候选人 | 403 | 403 |
| 候选人申请过其职位的已登录雇主 | 200 | 403 |
| 无对应投递关系的雇主 | 403 | 403 |
| 未登录、无效或过期令牌、账号不存在 | 401 | 401 |

## 接口

- `GET /users/candidates/{candidate_id}/profile`：复用完整资料读取，返回 `user_id`、`display_name`、`resume_text`、`skills`；不返回邮箱、密码哈希或认证令牌。服务端连接 Application 和 Job，核对候选人投递记录与职位的 employer_id；无对应投递关系返回 403。身份和关系均由服务端查询，不接受客户端声明。申请处于 Pending、Interviewing、Rejected、Accepted 均可读取，职位软删除后保留历史投递读取权限；投递记录移除后不再授权，职位所属雇主以当前数据库记录为准。
- `PATCH /users/candidates/{candidate_id}/profile`：仅限候选人本人；可局部更新 `resume_text`，省略字段保留原值，空字符串清空，`null` 或非字符串返回 422。已有名称和技能编辑规则保持适用。
- `POST /users/candidate/profile`：首次填写本人资料；归属来自认证用户，重复创建返回 409，不能用来覆盖他人简历。
- 请求不能指定 `user_id`、`candidate_id`、`role` 等归属或权限字段；严格请求校验返回 422。
- 获准读取的目标账号或资料不存在，或目标不是候选人，返回 404；UUID 格式错误返回 422。其他候选人读取非本人 ID 时先返回 403。

简历以纯文本保存，保留换行、中文、首尾空白；前端使用 React 文本节点转义 HTML。当前没有额外的简历长度上限，也没有版本号或冲突检测；同一字段连续保存以后提交的值为准。PDF/Word 上传、解析及下载未在本项需求中实现。

## 接入边界

独立应用 `app.candidate_main:app` 已包含上述路由。候选人的读取和编辑页面继续使用现有入口，提示已更新。雇主页面所有者可通过读取接口展示简历，不应显示编辑操作；服务端仍会拒绝雇主直接发起的修改请求。当前没有新增雇主简历列表或详情页面。

团队原应用 `app.main:app` 未改动，需由入口所有者按 `CANDIDATE_INTEGRATION.md` 挂载候选人路由。团队模型和 schema 的旧注释可能仍描述“仅本人读取”，这些文件按归属规范保持原样，以本文及候选人需求摘录中的新权限为准。

本项未切换先前建立的六表开发库，沿用当前候选人运行应用的数据库配置和模型，无需新增表或迁移。

# 技能标签选择器接入说明

2026-10-26，功能编号 CAN-005。候选人与雇主共用搜索、推荐、选择、自定义及移除标签的组件，保存时继续使用原有技能字符串数组，不新增表或迁移。

## 当前完成情况

- 候选人首次填写资料和已有资料编辑共用 CandidateForm，现已替换逐行技能输入为 SkillTagPicker。
- 输入 `j` 时可匹配 Java、JavaScript、Jest 等；大小写不影响搜索，前缀匹配优先，其余包含匹配随后，最多显示 8 条预置建议。
- 鼠标点击或方向键加 Enter 可添加标签，Escape 关闭建议。已选择的技能不重复推荐，标签可逐个删除，也可全部清空。
- 输入非空、没有同名预置项且尚未选择的文字时，在建议列表末尾显示“自定义：输入内容”。即使仍有部分匹配建议，也可以创建完整输入对应的自定义技能；无任何匹配时仍可使用自定义选项。
- 仅输入但未选择/创建的文字不是标签，提交时浏览器提示先完成选择或清空搜索框，避免误以为已保存。
- 未知的历史技能可正常回显和移除。保存失败时保持当前表单；提交中禁用组件。

显示名称如 Java、JavaScript 用于界面；实际保存的值为 `java`、`javascript`。自定义技能也去首尾空白、转小写并去重；C++、C#、Node.js 等标点保留，不做同义词替换，不把 Java 与 JavaScript 合并。现有后端仍独立进行技能规范化，匹配算法不变。

## 雇主页面接入

组件位于 `frontend/candidate/src/components/skills/SkillTagPicker.tsx`，预置目录和规范化辅助函数位于同目录 `skillCatalog.ts`；样式由组件自行导入。队友在自己的职位表单中维护技能数组，例如：

```tsx
import { useState } from 'react'
import { SkillTagPicker } from './实际相对路径/SkillTagPicker'

const [requiredSkills, setRequiredSkills] = useState<string[]>(existingRequiredSkills)

<SkillTagPicker
  label="职位所需技能"
  value={requiredSkills}
  onChange={setRequiredSkills}
  disabled={submitting}
/>
```

以上是组件接入片段，需放入队友现有 React 组件，并使用其实际数据、导入路径和提交逻辑。表单应使用标准原生校验，不能以 `noValidate` 绕过组件未完成输入的提示。

将 requiredSkills 映射到雇主接口已有的技能字段，由职位服务规范化并写入 JobSkill。不能把示例当成已经存在的职位保存接口：当前独立应用尚无雇主职位新增/编辑接口，雇主页面和保存服务由相应所有者接入。保存时必须校验雇主身份与职位归属，候选人不能借同一组件修改 JobSkill。

同一组件支持 `options` 参数，类型为 `{ value: string; label: string }[]`，可扩展预置目录；value 按原有规范化规则保存，label 仅用于显示。若以后从服务端加载建议，应先完成相应接口权限及字段范围审查。

## 目录、权限与边界

- 本次推荐使用本地共享预置目录，不向数据库发送搜索查询，不读取其他人的简历、技能或职位草稿。
- 自定义标签先存在当前表单中；点击保存后，候选人技能通过原权限接口写入本人的 CandidateSkill；雇主端接入后写入自己的职位 JobSkill。
- 创建自定义标签不等于修改公共目录，不会自动把某个人的输入公开为所有用户的推荐，也不会创建新的账号权限。
- 当前目录是可扩展的初始目录，不是完整行业词库；没有模糊纠错、同义词合并、简历自动提取或全库热门技能统计。
- 自定义标签按纯文本显示，不执行 HTML。保留已有后端字符串约束，本次没有新增长度、数量或行业分类规则。
- 简历仍沿用已有纯文本输入，本项没有新增 PDF/Word 上传或解析。

# 四类编辑器的版本保护与检查更新验证

日期：2026-11-23（Asia/Shanghai）。实施前已 fetch GitHub main，远端 main 与本地 HEAD 均为 `b21d9d9033d130326fdbc5f77c09d71ff42cba6d`。本报告针对该提交加本轮未提交补丁；没有提交、推送或迁移共享数据库。机器可读结果见 [editor-version-verification.json](editor-version-verification.json)。旧报告仍是其原始版本与执行时点的证据。

## 实施范围与用户操作

| 编辑入口 | 保护范围 | 本轮变化 |
|---|---|---|
| 候选人资料 | 姓名、简历、完整技能集合 | 保留已有版本保护，新增常驻“检查更新” |
| 公司资料 | 公司名称、公司描述 | 新增版本保护与“检查更新” |
| 职位编辑 | 标题、描述、完整要求技能集合 | 保留已有版本保护，新增“检查更新” |
| 职位申请人卡片 | 申请状态 | 新增版本保护与每张卡片独立的“检查更新” |

已经核对当前后端更新路由；上述四处是保存已加载编辑状态的入口。新建资料、发布职位、投递、预约与删除保留原有原子操作契约。新职位没有已保存版本，因此创建页不显示检查按钮。

按钮名为“检查更新”，位于保存旁边。版本相同则保持全部输入并提示当前已是最新版本；版本不同且有草稿时，先确认丢弃本页修改。取消后保留草稿及旧版本，禁用保存；确认后才应用读取结果。读取失败保留草稿，允许重试。未添加的技能搜索文字也算草稿。刷新某张申请卡片只更新该卡片的状态及版本，不推进其他卡片草稿的版本。现有 fetch、JSON 和 Cookie/CSRF 请求封装继续使用。

## 后端契约与迁移

新增迁移 `8c3d0e5f7a21`，接在 `7b2c9d4e6f10` 后，为 `employer_profile`、`application` 增加非空正整数版本，Python 字段及数据库默认值均为 1。旧记录补为 1，保留其他字段。公司资料创建及读取、雇主申请列表、候选人申请读取与状态保存响应带版本；公司创建请求不能指定版本。

`PATCH /employer/company` 与 `PATCH /employer/applications/{id}/status` 必须显式带读取时的严格正整数 `version`。缺失、null、布尔值、字符串、非正数及小数均 422。认证、归属及存在性检查仍优先于版本冲突。父记录使用 `FOR UPDATE` 加 `populate_existing`，在同一事务比较版本、更新和递增；过期版本返回 409 与 `{"detail":"Resource version conflict"}`。提交前 flush 并捕获独立 DTO，提交失败一起回滚字段与版本。

公司只带版本的请求检查新鲜度但不递增；含编辑字段的保存即使值相同也递增一次。状态接口仍要求 `status`，保持四种状态任意切换及预约不丢失；同值保存也递增。没有缺版本的兼容绕过。

部署时停止编辑写入，在正确应用数据库配置下执行 `cd backend`、`python -m alembic upgrade head`，并配套部署前后端、刷新旧标签页。本轮只在随机新建的隔离测试库运行迁移；未修改正在使用的应用数据库。

## 修前证据、根因与新增判据

旧公司更新直接写字段并提交；旧申请状态更新虽然有行锁，却未检查页面读取时的状态版本。行锁只能串行执行请求，不能识别旧页面的意图，因此第二次保存仍会静默覆盖。`test_stale_company_or_status_tab_cannot_overwrite_newer_save` 的公司和申请两个参数，在补丁前实际执行：第一请求 200，第二旧页面请求仍为 200，两个用例均失败。原始日志保留于本地 `tmp/all-editor-version-20261123/integration.log` 与 XML。测试为保存修前证据兼容“响应没有版本”，修后其他独立用例明确断言版本必为 1，不构成生产兼容通道。

修后不只让这两个复现转绿，还新增以下根因邻域：

- 两个和三个请求预先捕获相同版本，同时修改公司资料或不同申请状态，恰好一个 200，其余 409；最终值来自赢家，版本只增一次。
- 严格版本校验、公司空操作、显式同值、空描述清空及省略字段保留；状态仍必须存在。
- 真实 flush 后注入提交失败，验证回滚；预加载旧 ORM 实例后由另一会话提交，验证缓存不会隐藏新版本；提交后紧接另一保存，验证先前响应不混入后一次版本。
- 401/403/404 优先级、创建不能自定公司版本；已有预约、状态全转移、匹配分不受无关资料文字变化影响。
- 7b 旧库有数据升级、原字段逐项保留、新 SQL 插入默认 1、非空/正数约束、模型字段默认、降级后重新升级。迁移测试另建随机库并在 finally 删除，绝不降级应用库。
- 浏览器同版本检查保持草稿、双击只发一次读取、读取失败、取消/确认、真实 409、失败重载、保存时版本、未添加技能查询，以及两个申请卡片相互隔离。
- 公司和申请状态在三引擎、双语言中实际打开两个页面，提交版本序列均为 `[1,1,2]`，响应为 200/409/200，最终版本 3。候选人和职位沿用原真实双标签页回归。

测试文件为 `backend/tests/candidate/test_extended_versions.py`、`tests/unit/test_versions.py` 与 `frontend/tests/specialized/editor_update_checks.mjs`；旧合法 PATCH 测试显式补版本，顺序状态切换推进预期版本，竞态用例固定同一旧版本。没有通用“保存前重新 GET 最新版本”辅助函数，也没有削弱冲突断言。

# 任务 P6：差分测试——Python 打分 vs SQL 打分 vs 两端视图

**分支**：`test/P6`　**依赖**：P0 已合并　**预计**：3 小时

## 目标

用"同一规格的多个独立实现互为 oracle"的差分测试（differential testing）验证匹配分数：

1. Python `match_score` 与一条**独立编写的 SQL 查询**在同一数据上逐行一致；
2. 候选人推荐接口与雇主申请人接口对同一 (候选人, 职位) 给出相同分数（FP-MATCH-1"两端调用同一实现"的可观察证据）；
3. 两端排序分别符合各自的平局规则。

## 具体要求

### 1. `test_matching_sql.py`

- 用 `random.Random(4801)` 生成 40 个候选人、15 个职位，技能来自词表（含大小写、空白变体），
  通过**真实接口**写入（保证归一化走真实路径）。
- 独立 SQL（自己写，`text()` + 绑定参数）：对每个 (候选人, 职位) 计算
  `CASE WHEN count(required)=0 THEN 100 ELSE floor(100.0*count(交集)/count(required)) END`。
  注意：数据库里的技能已是归一化后的值，SQL 不再做 lower/trim。
- 用真实 `match_score` 对从库里读出的技能列表计算，与 SQL 结果对比全部 600 对。
- 不一致时打印最小反例：两侧技能列表、SQL 值、Python 值。

### 2. `test_cross_view.py`

- 同样的数据：每个候选人投递全部职位（或随机一半）。
- 对每个候选人调用 `GET /candidate/jobs`，对每个职位调用 `GET /employer/jobs/{id}/applicants`；
  把两边的 (candidate_id, job_id) → score 拼成两张表，断言完全相等。
- 排序检查：候选人列表按 (−score, title.casefold() 或 lower(), job_id) 非降；
  申请人列表按 (−score, display_name lower, candidate_id) 非降。用独立的排序键函数，不调用实现里的排序。
- 故意构造平局：至少 3 个同分职位标题只差大小写；至少 3 个同分候选人名字只差大小写。

### 3. 证据

`evidence("differential", {"pairs": 600, "sql_mismatch": 0, "cross_view_pairs": N, "tie_groups": M})`

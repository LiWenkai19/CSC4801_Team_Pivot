## 具体要求

### 1. `tests/advanced/requirements.txt`

全部 `==` 精确版本，一次性写全后续任务要用的依赖（后续任务不再修改此文件）：
`hypothesis`、`z3-solver`、`mutmut`、`schemathesis`、`pytest-cov`、`coverage`。
选择在 Python 3.12 上能装、彼此兼容的最新稳定版；实际在本机 `pip install -r` 验证。
文件第一行注释：`# 高级套件专用，不进入 Docker 镜像；必测依赖在 requirements.lock`。

### 2. `tests/advanced/support/pg.py`

提供一个上下文管理器 `disposable_postgres()`，返回一个 SQLAlchemy URL 字符串：

- 若环境变量 `ADVANCED_PG_URL` 已设置（CI 场景，指向一次性服务）：直接使用它作为管理连接源；
- 否则用 `initdb`/`pg_ctl` 在临时目录建新集群、随机端口、仅监听 127.0.0.1，退出时停止。
  `PG_BIN` 环境变量或 `--pg-bin` 参数指定 PostgreSQL 服务器工具目录。
- 拒绝非 loopback 主机。

### 3. `tests/advanced/conftest.py`

- 模块级在任何 `app` 导入前设置：`APP_NAME`、`COOKIE_SECURE=false`、`DATABASE_URL`（占位）。
  `sys.path` 加入 `backend/`。
- session 级夹具 `engine`：在 `ADVANCED_PG_URL`（由 run.py 传入）上
  `CREATE DATABASE advanced_<随机>`，跑 `alembic upgrade head`，测试结束 `DROP ... WITH (FORCE)`。
  参照 `backend/tests/candidate/conftest.py`。
- `clean_tables`（**不要 autouse**，由需要的测试显式使用）：TRUNCATE 全部表。
- `client`：真实 `app.main.app`，`get_db` 覆盖为测试库；每次响应后清空 Cookie 罐。
- `account(role="candidate"|"employer", skills=None, name=None)`：通过真实注册 + 资料接口创建，
  返回 `(headers, user_id)`。
- `evidence(name, data)`：把 JSON 写到 `$ADVANCED_OUT/<mode>/<name>.json`。
- `utc_future(days=1, minutes=0)`：返回 UTC aware datetime。
- 无数据库的测试（如 formal）不能因为没有 PG 而失败：数据库夹具只在被请求时才连接。

### 4. `tests/advanced/support/traces.py`

定义轨迹事件格式（P2 写，P3 读），只要数据结构 + JSON 读写，不写业务逻辑：

```python
@dataclass(frozen=True)
class Event:
    step: int
    action: str              # "apply" | "set_status" | "create_slot" | "book" | "delete_slot" | "observe"
    ok: bool                 # 操作是否成功
    props: frozenset[str]    # 本步之后成立的原子命题，例如 "booked:a1:s1"、"available:s1"、"status:a1:Interviewing"
```

提供 `write_trace(path, events)`、`read_traces(dir) -> list[list[Event]]`。在 README 写明命题命名规则。

### 5. `tests/advanced/run.py`

- 用法：`python tests/advanced/run.py <mode> [--out DIR] [--pg-bin DIR] [--max-examples N]`
- **自动发现模式**：`tests/advanced/` 下除 `support`、`experiments`、`__pycache__` 外的子目录即模式。
  目录内有 `entry.py` → 以子进程 `python entry.py` 运行；否则 → `pytest <目录>`。
  目录内有空文件 `SLOW` → 不进 `fast`。
- 特殊模式：`fast`（所有非 SLOW）、`all`（全部）、`list`（打印模式及是否 SLOW）。
- `--out` 必须在仓库外且为空/不存在；默认在系统临时目录新建。
- 统一环境：`PYTHONHASHSEED=4801`、`PYTHONUTF8=1`、`PYTHONPATH` 含 `backend/` 与 `tests/advanced/`、
  `ADVANCED_OUT=<out>`、`ADVANCED_PG_URL=<url>`、`ADVANCED_MAX_EXAMPLES`（若传入）、
  清除外部传入的 `DATABASE_*`、`CANDIDATE_TEST_*`、`EMPLOYER_TEST_*`。
- 每个模式写 `<out>/<mode>/result.json`（命令、退出码、耗时、junit 路径），pytest 模式加 `--junitxml`。
- 顶层写 `<out>/summary.json`：commit SHA、`git status --porcelain` 是否干净、各模式结果、总退出码。
- 任一模式失败 → 非零退出。只有需要数据库的模式才启动 PG（可在模式目录放空文件 `NEEDS_DB`）。

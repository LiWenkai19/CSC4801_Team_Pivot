## 具体要求

### 1. 编码（`encoding.py`）

- `n = |R|`、`k = |C ∩ R|` 为整数变量；约束 `n >= 1`、`0 <= k <= n`。
- 分数 `score = (100*k) div n`（Z3 整数除法），另一个定义 `n = 0 -> score = 100`。
- 集合编码：有界全集 `U` 大小为 6，`C`、`R` 用 6 个布尔变量向量表示，`k`、`n` 用 `Sum(If(...))` 定义。

### 2. `test_matching_theory.py`

每个性质一个测试，**断言"性质取反"不可满足（`unsat`）**：

| ID | 性质 | 条款 |
|---|---|---|
| T1 | `0 <= score <= 100` | 分数为 0–100 的整数 |
| T2 | `k = n -> score = 100`；`k = 0 -> score = 0` | 示例行 1、3 |
| T3 | `score*n <= 100k < (score+1)*n`（floor 的定义） | `floor(100*|C∩R|/|R|)` |
| T4 | `k1 <= k2 -> score(k1) <= score(k2)`（同一 n） | 排序合理性 |
| T5 | 集合编码下：`score = 100 <-> R ⊆ C`（n ≥ 1） | 满分语义 |
| T6 | 集合编码下：向 C 添加不在 R 中的元素，分数不变 | 无关技能不影响 |
| T7 | `n = 2, k = 1 -> score = 50` | 示例行 2 |

每个测试上方用注释写出 Hoare 三元组，例如：
`# {n >= 1 ∧ 0 <= k <= n}  score := (100*k) div n  {0 <= score <= 100}`

另外写 2 个**负向测试**：故意证明一个假性质（例如 `score = round(100k/n)` 恒等于 floor 版本），
断言求解器返回 `sat` 并打印反例模型——证明编码不是平凡为真。

### 3. `test_spec_to_code.py`（连接规格与实现）

对有界全集 `{a,b,c,d,e}` 的所有子集对（`2^5 × 2^5 = 1024` 对），用真实 `match_score` 计算，
与 Z3 编码在该具体赋值下求得的值（或等价 Python 公式）逐一比对；全部一致。
另外对每个 T 性质，在这 1024 对上用真实实现检查一次（有界穷举，不是证明，报告里要区分）。

### 4. `docs/testing/FORMAL_MATCHING.md`

- 方法：Hoare 逻辑 + SMT；"证明的对象是规格公式，实现通过有界穷举对拍关联"——**写清楚不夸大**。
- 表格：条款 → 性质 → Hoare 三元组 → 结果（unsat / 穷举 1024 一致）→ 耗时。
- 负向测试的反例输出。
- 局限：未证明 Python 代码本身；归一化（strip/lower/去重）不在 SMT 模型内，由 P1 属性测试覆盖。

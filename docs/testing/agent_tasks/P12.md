# 任务 P12（可选）：依赖与密钥扫描进 CI

**分支**：`test/P12`　**依赖**：无（只新增一个独立 workflow 文件）　**预计**：2 小时

## 目标

为 FP-SEC-4（无真实密钥）和依赖安全提供持续证据：在独立 workflow 里运行
`gitleaks`（全历史密钥扫描）、`pip-audit`（Python 依赖）、`npm audit`（前端依赖），
并对每个命中做人工归因。

## 允许修改

- 新增：`.github/workflows/security.yml`
- 新增：`.gitleaks.toml`（仅当需要允许列表，例如演示密码 `demo-local-only`、`.env.example` 占位符）
- 新增：`docs/testing/SECURITY_SCANS.md`

**不要修改 `ci.yml`**（它属于 P0/P11）。

## 具体要求

1. `security.yml`：触发 `push`（main）、`pull_request`、每周 `schedule`、`workflow_dispatch`；`permissions: contents: read`。
2. 三个 job：
   - `gitleaks`：`actions/checkout@v4` 带 `fetch-depth: 0`；用 gitleaks 官方二进制（固定版本，校验 checksum）
     运行 `gitleaks git . --redact=100 --no-banner --exit-code 1`；**不要用需要 license key 的 action 版本**。
   - `pip-audit`：`pip install pip-audit==<固定版本>`，`pip-audit -r requirements.lock --strict`。
   - `npm-audit`：`npm --prefix frontend ci` 后 `npm --prefix frontend audit --omit=dev --audit-level=high`。
3. 本地先各跑一次，逐条归因写进 `docs/testing/SECURITY_SCANS.md`：
   - 密钥命中：是否真实密钥（演示密码/占位符/测试合成值 → 加允许列表并写理由；真实密钥 → **立刻停下报告人类，不要在任何地方写出它的值**）；
   - 依赖漏洞：是否有可达代码路径；不可达的写理由；需要升级的列出，但**不要擅自改锁文件**，交给人类决定。
4. 允许列表必须精确到文件 + 规则或具体字符串，不能整体关闭规则。

## 验收

- 三个扫描本地运行结果与归因写入文档；
- `python -c "import yaml;yaml.safe_load(open('.github/workflows/security.yml'))"` 通过；
- 推送后 workflow 绿色，或红色但每个命中已归因并在汇报中请人类决定。

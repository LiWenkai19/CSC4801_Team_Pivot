让 `python tests/run_tests.py`（课程要求的唯一必测命令，也在 Docker 镜像内运行）包含基于性质的测试，
覆盖 FP-MATCH-1 的匹配分数和技能归一化。

## 具体要求

1. `requirements.lock` 末尾新增一段，带注释 `# Property-based unit tests (FP-MATCH-1)`，
   写入 `hypothesis==<版本>` 及其所有运行时依赖（例如 `attrs`、`sortedcontainers`；以实际 `pip install` 解析为准）。
   确认 `pip install -r requirements.txt` 在干净 venv 里成功。
2. 在测试文件里写一个**独立 oracle**：`Fraction` + 集合交 + `math.floor`，严格按需求文字实现；
   **不得**调用 `match_score` 或 `normalize_skills` 实现 oracle。
3. 策略：
   - 技能词：`st.text(alphabet=st.characters(blacklist_categories=("Cs",)), max_size=12)`
     与固定词表 `["Python","SQL","Rust","C++","C#",".NET","机器学习","ß","SS","İ","i̇",""]`
     用 `st.one_of` 混合；外加随机前后空白（`" "`, `"\t"`, `"\n"`）。
   - 列表：`st.lists(word, max_size=10)`。
4. 测试函数（名字固定，后续写进 README 映射表）：
   - `test_fp_match_1_property_score_is_bounded_integer`
   - `test_fp_match_1_property_equals_independent_oracle`
   - `test_fp_match_1_property_empty_required_is_100`
   - `test_fp_match_1_property_invariant_under_permutation_duplication_whitespace`
   - `test_fp_match_1_property_irrelevant_skill_does_not_change_score`
   - `test_fp_match_1_property_adding_required_skill_never_decreases`
   - `test_fp_match_1_property_monotone_in_overlap`
   - `test_fp_match_1_property_normalize_is_idempotent_and_canonical`
   - `test_fp_match_1_property_inputs_are_not_mutated`
5. 每个测试 `@settings(derandomize=True, max_examples=200, deadline=None, database=None)`；
   `database=None` 避免在镜像内写 `.hypothesis/`。
6. 文件顶部 docstring 说明：这是 FP-MATCH-1 的性质测试，oracle 独立于实现，规模固定，可复现。
7. 大小写：`str.lower()` 对 `ß`、`İ` 的行为以需求"转换为小写"理解为 Python `str.lower`；
   若你认为需求有歧义，在汇报里指出，**不要改实现**。

## 自检（必须做并在汇报里写结果）

`round` 而非 `floor`，`test_fp_match_1_property_equals_independent_oracle` 必须变红并给出最小反例。

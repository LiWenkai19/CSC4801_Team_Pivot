# Contract F3 — `SkillTagPicker` HTML-escaping behaviour

**Status of this file: written by the experiment owner before any generated test
existed. It is the only behaviour description given to the generator agent.**

- Normative source: `docs/REQUIREMENTS.md` **FP-SEC-3**; `SPEC.md` §“Security
  Controls → Access control and safe rendering”.
- Target: `frontend/src/components/skills/SkillTagPicker.tsx`.
- Calling convention (same as the existing rendering unit test): transpile the
  TSX source with `typescript`, load the React component with a tiny module
  loader, and render it with `react-dom/server`'s `renderToStaticMarkup`.
  The public component used by the existing test is the default export of
  `frontend/src/components/skills/CandidateSkillPicker.tsx`; it takes
  `{value: string[], onChange: (next: string[]) => void}` and must be rendered
  inside the default export of `frontend/src/i18n/LanguageProvider.tsx`.
- Import path for the generated test helper:
  `import {renderSkills} from './render_helper.mjs'`, where
  `renderSkills(value)` performs exactly that render and returns the HTML string.

## 1. Input

`value` — a non-empty or empty `list[str]` of candidate skill names. The names are
user-controlled data. They may contain any Unicode text, including HTML/JS
metacharacters: `<`, `>`, `&`, `"`, `'`, `/`.

## 2. Output

A deterministic HTML string produced by React's static renderer. It contains the
selected-skill tags and a search input. There is no network access and no error
for ordinary strings.

## 3. Obligations (FP-SEC-3)

1. **Text, not markup.** Every skill name must be emitted as HTML text: each
   `<` becomes `&lt;`, `>` becomes `&gt;`, `&` becomes `&amp;`, `"` becomes
   `&quot;`, `'` becomes `&#x27;` (React's escaping; an equivalent numeric
   character reference is acceptable for `'`).
2. **No executable markup.** After rendering a name such as
   `<script>alert(1)</script>`, the HTML must not contain a raw `<script` opening
   tag (case-insensitive) and must not contain the unescaped literal
   `<script>alert(1)</script>`.
3. **Attributes too.** Text copied into attributes (for example
   `aria-label="Remove <name>"`) must be attribute-escaped; a name containing a
   double quote must not terminate the attribute early.
4. **Content preserved.** Un-escaping the emitted text yields the original visible
   characters (modulo the component's documented display normalisation, see
   ambiguities). Unicode, spaces and punctuation survive.
5. **No double rendering.** A malicious name must not be interpreted as HTML or
   as a React element; it is a single text node.

## 4. Hand-calculated expected values

React 19's `renderToStaticMarkup` escapes the five characters above.

1. `value = ['<script>alert(1)</script>']`
   - Expected escaped fragment: `&lt;script&gt;alert(1)&lt;/script&gt;`
   - Must **not** match `/<script(?:\s|>)/i`.
   - The remove control's label must contain the escaped name, not a raw `<`:
     `aria-label="Remove &lt;script&gt;alert(1)&lt;/script&gt;"`.
2. `value = ['onmouseover="x"']`
   - Expected escaped fragment: `onmouseover=&quot;x&quot;`
   - The raw literal `onmouseover="x"` must not occur.
3. `value = ['a&b']`
   - Expected escaped fragment: `a&amp;b`
   - The raw literal `a&b` must not occur.
4. Boundary: `value = []` renders the picker without any tag; no exception.
5. Ordinary text: `value = ['中文 résumé 🙂', 'c++']` keeps the Unicode text and
   `c++` visible (case handling is an ambiguity below; compare
   case-insensitively if needed).

## 5. Partitions

- **Valid:** ordinary ASCII/Unicode skills, several skills at once.
- **Boundary:** empty list; a single-character skill; text that is only
  metacharacters (`'<'`, `'"'`, `'&'`).
- **Invalid / hostile:** script tags, quoted attribute breakouts, ampersand
  entities (`&lt;` as literal text must itself become `&amp;lt;`), mixed
  case HTML, closing tags.

## 6. Ambiguities to record

1. The component may normalise display text (for example lowercase it, or restore
   a catalogue spelling). The contract only fixes escaping and content
   preservation; assertions should not require an exact whole-HTML string and
   should compare case-insensitively when the component's normalisation is
   unknown.
2. Attribute order, whitespace and CSS class names are not part of the contract.
3. Whether the remove control is a `<button>` with `aria-label` or another element
   is not fixed by the requirements; assert the escaped value occurs somewhere,
   not a specific tag layout.
4. `renderToStaticMarkup` does not execute JavaScript, so “not executable” is
   demonstrated by the absence of raw markup, not by running a browser.
5. The component's list is controlled by the `value` prop; typing/search
   behaviour is outside this contract.

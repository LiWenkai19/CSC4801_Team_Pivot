# 候选人模块需求摘录

依据 docs/REQUIREMENTS 中文翻译.md；用户后续明确更新的需求优先，以下注明最新差异。

- FP-CAN-1（用户于 2026-10-26 更新）：候选人仅读取/编辑本人显示名称、持久化技能与纯文本简历；已登录雇主仅可读取申请过自己职位的候选人资料和简历，但不得修改。其他候选人读取或修改必须 403，匿名请求必须 401。
- FP-CAN-2：列出全部未删除职位，显示标题、公司、技能、分数和描述入口，分数降序及规定同分排序。
- FP-CAN-3：每职位一次申请、Pending 初始状态、重复拒绝；本人申请展示职位/公司/状态/预约，不能查看他人或修改状态。
- FP-MATCH-1（用户于 2026-10-26 更新，CAN-006）：评分算法暂用占位符，统一返回 0 并标记 placeholder，后续开发真实算法；当前不按旧技能交集公式计算分数。双方使用同一占位入口，职位按分数降序，同分按标题和 ID 稳定排序。技能输入规范化保留。
- FP-SCHED-2/3：本人 Interviewing 申请、对应雇主未来空闲时段、申请无预约；数据库原子性，竞争失败409/Slot already booked，状态变化保留预约。
- FP-AUTH-3/SEC-1～4：服务端权限，401/403/404 区分，ORM 绑定值、安全文本渲染、无真实机密和隔离测试。

共享表由本模块提供以供队友接入；完整雇主管理与时段管理不在本次 candidate flow 交付范围。测试与团队未完成项见 README 映射。

# 雇主模块需求摘录

本文件从仓库根目录 `REQUIREMENTS 中文翻译.md` 摘录与本模块直接相关的条目，供实现复核。规范原文仍是根目录需求文档。

## FP-AUTH-3：服务端授权

每一个受保护的操作都**必须**在服务端强制执行角色与所有权校验；仅在 UI 中隐藏按钮是不够的。可观察的响应契约：

- 未认证的请求：`401 Unauthorized`（未认证）或重定向到登录页；
- 已认证但角色或所有者不符的用户：`403 Forbidden`（禁止访问）；
- 调用者本应有权访问、但对象不存在的情况：`404 Not Found`（未找到）。

## FP-EMP-1：公司资料

雇主**必须**能够查看和编辑公司资料，资料至少包含公司名称与描述。

## FP-EMP-2：职位发布

雇主**必须**能够创建、查看、编辑和删除自己的职位发布。每份职位发布**必须**包含非空的标题与描述，以及一份所需技能列表；该列表可以为空。雇主在试图编辑、删除其他雇主的职位发布或管理其申请人时，**必须**收到 `403`。

没有申请且没有面试时段的职位**必须**可以删除。如果存在任一一类关联记录，删除操作**必须**以 `409 Conflict`（冲突）失败，且职位与关联记录保持不变。

## FP-EMP-3：申请人管理

对于每一个自己拥有的职位，雇主**必须**能够查看其申请人列表，并按匹配分数从高到低排序。每一行**必须**显示候选人身份、技能、匹配分数、申请状态以及面试预约（如有）。

拥有该职位的雇主**必须**能够将申请设置为且仅能设置为以下状态之一：`Pending`、`Interviewing`、`Rejected`、`Accepted`。其他雇主与候选人**不得**更改该状态。

申请人列表复用组员已实现的 `GET /employer/jobs/{job_id}/applications`；本模块只负责状态修改。

## FP-MATCH-1：分数定义（共享契约）

匹配分数是确定性的技能重叠分数，简历文本不参与。技能规范化：去除首尾空白、转换为小写、移除空值、去除重复项。`score = 100`（所需技能为空）或 `floor(100 * |C ∩ R| / |R|)`。候选人视图与雇主视图调用同一实现。本轮组员以占位实现返回 0，本模块不重复实现评分。

## FP-SCHED-2：预约资格（相关约束）

如果已预约的申请之后离开 `Interviewing` 状态，其预约**必须**保持与该申请的关联，且该时段**必须**保持不可用。因此状态修改不触碰 `booking`。

## FP-SEC-1：对象访问

在请求中更改对象 ID **不得**绕过 FP-AUTH-3。与本模块相关的边界：

1. 一个雇主不能修改另一个雇主的职位，也不能读取其申请人列表；
2. 候选人不能修改申请状态。

## FP-SEC-2：SQL 注入

所有涉及用户可控取值的数据库访问**必须**使用参数化查询、正确使用的 ORM，或等价的安全 API。禁止将原始用户输入拼接到查询中。至少一个单元测试**必须**向查询构建或数据访问逻辑传入 SQL 元字符，并验证该输入始终是绑定值而不是可执行的 SQL。
